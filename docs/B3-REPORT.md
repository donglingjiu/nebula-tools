## 附件8：军规 #16 自愈器纪律与误诊防护（2026-10-26）
- 案：第37发落盘块把#12归一函数默写走形——丢量词、替换式误用group(1)，该版N是潜伏凶器；第38发首版手术凭终端回显定靶，被CHx0断言当场拒付，零改动零误伤。字节级验伤（repr）定谳：回显中三处疑似伤情（迁移本戳/迁入齐/等于物环境）均系终端软回绕伪影，落盘字节全程干净，前轮噬字诊断撤回。若当时按回显做全文件盲归一，四处原史合法空格将被误毁。
- 法：一、N()是受控模板，只许整块复制既定正则（带量词与反向引用），禁默写禁简化；二、任何N()后必须正反双哨兵（新串在、残串不在），无断言的N视同未执行；三、伤情诊断只认文件字节（repr），不认终端回显——回显会说谎，字节不会；四、count==1断言不仅防漏改，更防误诊，拒付即证据。

## 附件9：军规 #17 断言精度与兑现锁链（2026-10-26）
- 案一：SENT-GO 断言凭记忆写 count==2（实际 1），误伤正确代码，零污染但浪费一轮。
- 案二（立规当轮自犯）：SHAPE 断言把编译器报错行数 4 当成出现次数——实际 5 处（26 行含 len(s2.Profiles) 与 s2.Profiles[0] 两处，编译器每行只报首处）；给 #17 立档的同一段代码，第一条断言即撞 #17。
- 案三：发版动作（CHANGELOG/verify-30）在部署缺席时仍独立执行，4dd3886 成虚账——仓库 v2.9.9、生产 v2.9.8、体检 28/2。
- 法：一、count==N 断言须以文件实数为准，禁凭记忆；报错行数≠出现次数；断言消息自带实数回显（SHAPE%d 式），拒付即自证。二、CHANGELOG/verify 发版动作必须锁死在部署健康之后（同一 && 链或 curl 版本探针前置门），虚账零容忍。
- 案四（幻觉 API）：T3 断言凭印象写 tx.Begin()——代码实为 novaDB.Begin()（标准模式 tx, err := db.Begin()，*sql.Tx 根本没有 Begin 方法），断言 token 在任何正确 Go 代码中都不存在，正确代码被幻觉断言当场拒付；先算后写零落盘救场。
- 案五（自败断言）：T4 断言 KLEFT 要求 return "", 0, 清零——但替换串 return "", 0, 0, 本身以被检模式为前缀，清零数学上不可能达成；内存变换本已正确却被断言误杀弃写（两段式纪律保证零半写），虚耗一轮。法：替换类后置断言须先验证「替换串不含被检模式」——模式为自身替换的前缀时清零式断言永假，应改用负向前瞻 (?!0) 或替换前后双计数校验。
- 案六（签名漏改）：T4 llmCallU 替换全部 return 语句却漏改签名声明 (string, int, error)——vet 精确报 87:20 too many return values；编译器兜底、两段式零半写、#18 第六拦（nova-box 缺席断链，生产零伤）。法：改返回值必同步改签名声明——替换枚举须覆盖「声明+全部 return」两处；编译期错误一律先于发版清零。
- 案七（枚举漏变体）：T4 return 替换按字面前缀 return "", 0, 枚举——ms 已计算的分支实为 return "", ms, err（第二值是变量非常量），字面枚举不命中；vet 每函数只报首个元数错（87:20 后又 113:18），逐个试错虚耗两轮。法：改返回值元数须结构化扫描全函数 return 按元数断言（值计数器含括号/引号感知），禁字面前缀枚举——变量变体（ms/0 之别）是字面枚举的天然盲区；编译器「修一个冒一个」即信号，应一次结构化清零。
- 案八（探针标记漂移）：T5 verify「对话页在位」探针 grep api/conversations——chat.js 实际以 /api+path 拼接风格构造请求路径，字面 api/conversations 不存在，探针必败（32/1）；同轮写文件+写探针，却未把探针模式对刚写盘的实文实跑。法：文件与探针同轮产出时，探针 grep 模式必须先对实文断言命中再入库——探针验的是实文，不是想象中的文件；同轮双清单（文件标记断言/探针模式）必须对齐。


## 附件10：军规 #18 部署顺序铁律（2026-10-26）
- 案：部署块把 pkill 排在 mv nova-box 之前——闸门失败 nova-box 缺席时 mv 断链、nohup 重启段从未执行，生产被杀且未拉起（http 000，体检 7/23 连带全红）。
- 首胜：立规次轮实战拦截——闸门再败、nova-box 缺席，test -x 前置断链，pkill 未及执行，生产全程 200。铁律生效首日即拦下同型事故。
- 法：一、test -x nova-box 必须排在 pkill 之前，弹药不在膛则整链在任何伤害发生前断掉；二、闸门失败即部署禁令，③ 不可独立于 ② 执行；三、生产死亡时第一动作救活、第二动作查案。
- 附记：回滚触发条件是 http≠200；生产健康时的预防性回滚属空放（一次约 3 秒、无损害）——回滚只对真失败开火。

## 附件11：军规 #19 预排即代码与写探针锁链（2026-10-26）
- 案一（预排笔误）：T3 鄰署预排 curl 笔误 1270.0.1（应 127.0.0.1），执行时靠 || 兜底救场——预排文本被逐字执行，笔误零侥幸。
- 案二（写探针空转）：e2e 冒烟（POST/DELETE 写操作）以分号独立于部署链，部署失败时对旧版空转——本例 CID 空零垃圾纯属侥幸，// 空段重定向结构上即隐患。
- 案三（正则笔误）：verify 写盘块 CJK 正则 \uff00-\xffef 笔误（\xff 两位转义吃掉第三个 f，范围反向），re 拒编译崩溃于第一行——零落盘纯属崩溃点在前。
- 法：一、预排即代码——预排块按生产代码同等纪律核对（token 逐字符、转义逐位、IP/路径逐段）；二、部署块的写操作探针必须锁在部署成功与版本探针之后（同一 && 链），只读诊断可分号独立；三、写探针自带 CID 有效性门（空/零即跳过），防旧版空转与重定向垃圾。
